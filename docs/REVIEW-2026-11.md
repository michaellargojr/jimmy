# Code review, November 2026

Scope: the whole repository as of commit `79574e3` (v0.1). Method:
read every file, build, type-check, run tests, measure the bundle, then fix. Every finding
below is either fixed in this branch or explicitly left with a reason. IDs are referenced
from code comments.

Severity: **C** crash or data loss, **P** performance, **W** PWA/offline, **Q** quality or
maintainability, **O** open question for the owner.

## Fixed

| ID | Sev | Where | Finding | Fix |
|---|---|---|---|---|
| C1 | C | `pages/Plan.tsx` | `routineLast(r!, ...)` ran before the `if (!r)` guard. Opening `/plan/<deleted id>` (browser history, stale link) threw and left a blank screen. | Guard before use; also "Routine not found" now renders for Overview pages. |
| C2 | C | `pages/Settings.tsx`, `db.ts` | Import did `JSON.parse` without try/catch and only checked two keys. A bad file produced an unhandled rejection and no feedback; a future-format file would have been imported blindly. | `normalizeSnapshot()` validates, upgrades v1 exports, rejects newer formats with a readable message. Import runs in a transaction; failure leaves data intact and says so. |
| C3 | C | app-wide | No error boundary. Any render exception = white screen with no way to get data out. | `components/ErrorBoundary.tsx` wraps the app: shows the error, Reload, Export (talks to Dexie directly), Go home. |
| C4 | C | `store.ts` | Every DB write was `void db.x.put()`. A quota or private-mode failure was silently dropped while the UI showed the data as saved. | `persist()` wrapper sets `persistError`; `App` renders a sticky banner with Export. `load()` failures set `loadError` with a dedicated screen. |
| C5 | C (dev) | `store.ts` | `load()` was not idempotent. React StrictMode runs effects twice in dev, so a fresh dev DB was seeded twice with different ids (duplicate routines, versions, workouts). | Shared in-flight promise: `load: () => (loading ??= doLoad())`. |
| C6 | C | `components/Overview.tsx` | The group button said "Circuit" for 4+ selections but created a `triset`. | `groupTypeFor(count)` in `grouping.ts`, used for both label and type. Tested. |
| C7 | Q/UX | `components/VersionSheet.tsx` | `Stepper` was declared inside the component body, so React remounted every stepper on each keystroke in the name field (flicker, lost focus on desktop). | Hoisted to module level. Also clamps repMin/repMax so min ≤ max on save. |
| C8 | UX | `components/Sound.ts` | `AudioContext` was created from a `useEffect` after a debounced wheel scroll, which is not a user gesture. On iOS that context starts suspended: the "hit max" ding was silent. | `installAudioUnlock()` creates/resumes the context on the next touch (installed by App when sound is on); `ding()` resumes if needed. |
| C9 | Q | `pages/OverviewPage.tsx` | `<span style={{display:'none'}}>{uid()}</span>` rendered a random id on every render. Leftover hack. | Removed. |
| C10 | W | `public/sw.js` | Navigation handler cached `index.html` even when the response was a 404/500, poisoning the offline fallback. | Only cache `fresh.ok` responses. |
| C11 | Q | `components/useHold.ts` | Hold timers in Plan rows and ExerciseCard were never cleared on unmount (callback after unmount). | Shared `useHold` hook clears on unmount; both call sites use it. |
| C12 | Q | `overload.ts` | `improved()` compared raw weights across units; switching a set to lbs produced a fake green check. | Compare in kg (`toKg`). Tested. |
| P1 | P | `derive.ts`, everywhere | `lastSession()` copied and sorted all workouts on every call. It was called per set row, per card, per keystroke in search, and (via P2) once per second on Live. With a year of history this is thousands of sorts per second. | `indexes.ts`: WeakMap-memoised `historyIndex`, `versionIndex`, `exerciseIndex`. All derive functions are O(1) lookups. |
| P2 | P | `pages/Live.tsx` | A `setInterval` -> `setState` tick in page state re-rendered the whole page (every card, row, history lookup) every second. | `<Timer>` leaf component owns the interval. |
| P3 | P | `pages/Live.tsx` | `localStorage.setItem` on every scroll event (frame rate) to remember the pane. | Debounced 150 ms; storage access wrapped in try/catch. |
| P4 | P | `components/WheelPicker.tsx` | Every debounce tick called `onChange` even when the value had not changed, so a slow drag wrote the workout to IndexedDB and re-rendered Live repeatedly. | De-duplicated against the last committed value. |
| P5 | P | `components/ExerciseCard.tsx` | `matchLast()` computed twice per set row; weight/rep ranges rebuilt with `range()` on each render. | Computed once per row; ranges are module constants. |
| P6 | P | many | `new Map(versions.map(...))` rebuilt per render in Home, Plan, Live, Overview, Library, AddExerciseSheet. | `versionIndex(versions).byId`. |
| P7 | P | `pages/Home.tsx` | Routine sort comparator called `routineLast()` (a full sort) twice per comparison, then again per row. | `lastFinishedByRoutine` from the index, one lookup per routine. |
| P8 | P | all components | Whole-store destructuring (`const {a,b} = useStore()`) re-rendered every subscriber on every write, including `IdeaFab` and `App`. | Selectors everywhere. |
| P9 | P/size | `App.tsx`, `store.ts` | dnd-kit (44 KB) and the seed (17 KB) shipped in the initial bundle though only Plan/Overview and first launch need them. | Lazy routes for Plan, Overview, Library, Settings; dynamic import of the seed. Main chunk 379 KB -> 314 KB (gz 123 -> 103 KB). All chunks are precached by the SW so offline still works. |
| W1 | W | `public/sw.js` | Static cache name `jimmy-v1`. Every deploy added new hashed assets and never removed old ones; the cache grew forever. | Build-time stamp (`swStamp` plugin in `vite.config.ts`): cache name from a hash of the asset list; old caches deleted on activate. |
| W2 | W | `public/sw.js`, `src/pwa.ts` | `skipWaiting()` on install meant a new worker took over while the old page kept running; with code splitting this would 404 lazy chunks. No update notice. | Worker waits; `pwa.ts` shows "new version ready" on Home; tap posts `SKIP_WAITING`; reload on `controllerchange`. `lazy.ts` reloads once on chunk failure. Update check on every return to foreground. |
| W3 | W | `main.tsx` | SW registered in dev, caching dev assets and confusing hot reload. | Registered only when `import.meta.env.PROD`. |
| W4 | W | `public/sw.js` | `addAll` with `.catch(()=>{})` meant one missing file silently skipped the whole precache. | `Promise.allSettled` per URL. Lazy chunks are precached so first launch works offline. |
| Q1 | Q | `model.ts`, `db.ts`, `Plan.tsx`, `OverviewPage.tsx` | Routine items had no identity; sortable lists keyed on `${versionId}-${index}`. After a drop the row under the finger changed identity (flicker) and two copies of the same version were indistinguishable. | `RoutineItem.id`, Dexie v2 upgrade back-fills, `normalizeSnapshot` fills on import, seed assigns. |
| Q2 | Q | `Plan.tsx`, `Overview.tsx` | The "leave the group if no longer adjacent" rule was duplicated. `Plan.move` (↑/↓) did not apply it at all, so a single-step move could leave a group split across non-adjacent rows. | `grouping.ts` with tests; both call sites use it; ↑/↓ now regroup too. |
| Q3 | Q | `seed/index.ts` | `verByName.get(name)!.id` threw a generic TypeError on a typo in `notion.ts`, i.e. a blank app on first launch. | Throws with the offending name and location; `seed.test.ts` runs the seed in CI. |
| Q4 | Q | repo | No lint, `noUnusedLocals` off, no tests for anything but overload rules. | ESLint flat config (TS + react-hooks), `noUnusedLocals/Parameters` on, 51 tests across 7 files, `pnpm check`, CI runs lint and tests before build. |
| Q5 | Q | `pages/Settings.tsx` | "built {currentYear}" was meaningless. | `__APP_VERSION__` and `__BUILD_TIME__` injected by Vite `define`. |
| Q6 | Q | `derive.ts` | Dead code: `workingReps()`, unused `before` parameter. | Removed. |
| Q7 | Q | `components/Sheet.tsx` | No Escape to close, no `aria-modal`. | Added. |
| Q8 | Q | `theme.css` | `.pager` had a fixed-height calc that Live overrode inline; `scroll-snap-type` set twice. No `prefers-reduced-motion`. | CSS owns the pager layout; reduced-motion rule added. |
| Q9 | Q | `pages/Settings.tsx` | File input kept its value, so re-importing the same file did nothing. | Reset after change; busy state while importing. |

## Left as is, on purpose

| ID | Where | Note |
|---|---|---|
| O1 | `overload.ts` | For one-arm versions "set 1 and set 2" are 1L and 1R, not 1L and 2L. Possibly intended. Documented in the file header; decide and adjust `verdict()`. |
| O2 | `store.ts` | Writes are not debounced. A note textarea writes the workout on every keystroke. Deliberate: data safety over write count on a device that can kill the app any time. Revisit only if Dexie shows up in a profile. |
| O3 | `model.ts` | `uid()` stays short (12 chars, ~41 random bits). Collision risk on one device is negligible; `crypto.randomUUID()` would triple id size in every export. |
| O4 | `VersionSheet.tsx` | Changing the muscle group of a version moves the whole base exercise (and sibling versions). Could be surprising; documented in the component header. |
| O5 | `AddExerciseSheet.tsx` | The muscle filter persists after picking an exercise. Arguably convenient. |
| O6 | dependencies | React 19, react-router 7, zustand 5, Vite 8, Vitest 5 are available. Not upgraded here: each is a behaviour change with no user-visible benefit today. Do them one at a time with `pnpm check` + a device test. `@dnd-kit/sortable` 10 in particular changes activation behaviour. |
| O7 | `index.html` | `user-scalable=no`: iOS ignores it for accessibility zoom but it stops double-tap zoom on buttons. Keep. |

## Verification performed

- `pnpm check`: typecheck (app + vite config), ESLint, 51 Vitest tests, all green.
- `pnpm build`: succeeds; `dist/sw.js` stamped with version and 14 precached assets.
- Playwright (Chromium, iPhone 13 viewport) against `vite preview`: first launch seeds,
  Home lists four routines and history, Plan and Overview lazy chunks load, a workout starts,
  the timer advances, a weight picked on the wheel appears in the row and survives a reload,
  Home shows IN PROGRESS without a redirect loop, Settings shows the version, Library loads,
  an unknown routine id shows "Routine not found" instead of crashing, both drafts render
  when flagged and are absent when not, and the console shows no errors.
- Not verified here: real iPhone gestures (hold vs drag vs swipe), the audio unlock, and the
  SW update banner on a second deploy. Test those on the device after the first deploy of
  this branch.
